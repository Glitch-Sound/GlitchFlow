# preview-navigation Specification

## Purpose

設計者がプレビュー上の処理や状態を確認しながら、対応する`.glf`の記述を素早く探して編集できるようにする機能である。
同じ表示内容が複数ある複雑なフローでも、記述位置を正確に選択する。

## Requirements

### Requirement: REQ-038 - 描画要素からDSLへの移動

WHEN 利用者がプレビュー上のメッセージ、DB・FILE State、SQL、Object、処理、複合フラグメントの見出しや分岐ラベルをクリックしたとき、GlitchFlowは SHALL 対応するDSL記述位置への移動を要求する。
移動できる要素はホバー時に操作可能なカーソルを表示する。

#### Scenario: REQ-038-S01 - 描画要素の移動

- **GIVEN** 同じラベルのメッセージが2件、DB Stateが2件、FILE State、SQL、Object、処理がある。
- **WHEN** 利用者が各要素をクリックする。
- **THEN** 各要素に対応する別々の記述行が選択される。
- **AND** ホバー時にはポインターカーソルが表示される。

#### Scenario: REQ-038-S02 - 分岐の移動

- **GIVEN** ネストした`alt`と`par`、`case`、`else`がある。
- **WHEN** 利用者がフラグメント見出しまたは分岐ラベルをクリックする。
- **THEN** それぞれの開始行または分岐行が選択される。

### Requirement: REQ-039 - エディタ表示と配置

WHEN 有効な移動要求を受けたとき、GlitchFlowは SHALL 対象`.glf`をテキストエディタで表示し、対象行全体を選択して中央付近へスクロールする。
既に表示中のDSLエディタがある場合はそのエディタグループを維持する。

#### Scenario: REQ-039-S01 - 配置と選択

- **GIVEN** 左側に`flow.glf`のエディタ、右側にそのプレビューがある。
- **WHEN** 利用者が右側のメッセージをクリックする。
- **THEN** 左側の`flow.glf`で対応行全体が選択され、画面内に表示される。
- **AND** プレビューは右側に残る。

### Requirement: REQ-040 - 位置情報の鮮度と安全性

IF 表示済み図の位置情報が現在の文書版と一致しない、または移動先が存在しない、THEN GlitchFlowは SHALL エディタの選択を変更せず、誤った位置へ移動しない。
再描画後は新しい位置情報を使用する。

#### Scenario: REQ-040-S01 - 古い位置の拒否

- **GIVEN** 図を表示した後、DSLの行を挿入し、再描画がまだ完了していない。
- **WHEN** 利用者が古い図の要素をクリックする。
- **THEN** エディタの選択は変わらない。
- **AND** 再描画完了後のクリックは新しい行へ移動する。

#### Scenario: REQ-040-S02 - 無効な要求の拒否

- **GIVEN** 位置情報を持たない図要素または不正な行番号の要求がある。
- **WHEN** 利用者が要素をクリックするかWebviewが要求を送る。
- **THEN** エディタの選択は変わらない。

#### Scenario: REQ-040-S03 - 図の操作を維持

- **GIVEN** 要素をクリックできるプレビューがある。
- **WHEN** 利用者がズーム、スクロール、テキスト選択を操作する。
- **THEN** ズーム、スクロール、テキスト選択は従来どおり動作する。
