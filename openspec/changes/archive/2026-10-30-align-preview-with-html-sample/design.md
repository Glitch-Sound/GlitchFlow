# Design

## Context

- 提案: [proposal.md](proposal.md)。
- 対象仕様: [REQ-022からREQ-025](specs/preview-appearance/spec.md)。
- 前提と制約: [描画規則](../../../tech.md#描画規則)、[レイアウトと描画](../../../tech.md#レイアウトと描画)、[責務の境界](../../../structure.md#設計責務の境界)に従う。
参照元は[HTML試作](../2026-10-29-glitchflow-spec/glitchflow-sample.html)、現行の基準画像は[基準DSL画像](../../../../docs/images/align-preview-login.png)である。

## Goals / Non-Goals

**Goals:**

- REQ-022からREQ-025の色、形、情報の階層、余白を基準DSLの図面に反映する。
- 自動計測と宣言順、時間順、文字選択、スクロールを保つ。

**Non-Goals:**

- HTML試作のソース欄をWebviewに追加しない。
- 固定座標、画像化、文字の省略による見た目合わせを行わない。

## Decisions

### D-01 - 暗色の図面パレットと種別の識別

- 対象: REQ-022 / REQ-022-S01、REQ-022-S02。
- 選択: Webview内に試作の暗色パレットをCSS変数として定義する。
図面の地、控えめな40px周期の横罫、操作部、ObjectカードをSVGとCSSで表す。
操作部のボタンは表示文字を左から`-`、`Reset`、`+`とし、読み上げ用の名前は日本語の操作名を維持する。
Coreのライフライン情報に既存IRのObject種別を渡し、枠と活性へ種別クラスを適用する。
Objectの表示名と種別を選択可能なSVGテキストで二段表示し、DSL上のObject IDは描画しない。
Object枠の下端と最初のメッセージラベルの上端は10px以上離す。
- 理由: ライトテーマでも同一の参照デザインを保ち、色と副題の両方で種別を判別できる。
- 代替案: VS Codeテーマ色だけに依存すると試作の配色を再現できない。
- 配置と依存: `src/core/layout/sequence-layout.ts`は種別を保持するだけとし、`src/webview/pages/preview/ui/render-preview.ts`と`src/webview/app/styles.css`が色を描画する。

### D-02 - メッセージと処理のラベルを計測して描く

- 対象: REQ-023 / REQ-023-S01。
- 選択: SVG内の背景矩形とテキストでメッセージのタグと処理カードを表す。
強調処理は幅、文字サイズ、太さ、アクセント色を変える。
通常処理も左アクセントと背景を持つ。
ラベルの描画寸法をレイアウト計算に反映し、隣のライフラインと矢印の先端に必要な余白を確保する。
カードと活性の水平距離、連続する処理カードの縦距離をそれぞれ8px以上にする。
応答直後の送信元の活性終了座標は応答線のY座標を使う。
Coreのメッセージ行の間隔を52pxから60pxに広げ、分岐直後は36pxから44pxに広げる。
最初のメッセージラベルはObject枠の下に11pxの空きを取る。
- 理由: HTML試作の情報階層へ近づけながら、ラベルの文字を選択、コピーできる。
- 代替案: SVGに`foreignObject`とHTMLを埋める方式はWebview内の寸法と選択挙動を複雑にする。
- 配置と依存: Coreのレイアウト計測とWebviewのSVG描画のみを変更する。

### D-03 - StateとSQLを見出し付きカードにする

- 対象: REQ-024 / REQ-024-S01、REQ-024-S02。
- 選択: DBとFILEのパネルに見出し帯と種別色の境界を付け、ライフラインとの間に短い破線を描く。
直後の同一DB SQLは現在の連続判定を使い、DBカード下部に接する幅の灰色領域と`SQL`見出しを描く。
独立したSQLは従来どおり単独の枠にする。
DB見出しには表名または`schema.table`、FILE見出しにはObjectの表示名を使い、DSL上のObject IDは描画しない。
パネルの寸法には見出し、表、SQL、テキスト余白を含める。
DBの数値型判定はschemaの列型を使い、レコードの表示文字列では外側の引用符を除く。
表示用の文字列と列幅の計測を同じ値にして、数値型をセル右端に、それ以外を左端に寄せる。
DBの列は表示時の等幅フォントでカラム名と値を測り、最大幅に左右各10pxの余白を加える。
短い列には最小幅を設け、SQLは表の幅に合わせる。
- 理由: 試作のDBとSQLのまとまりを再現し、既存のStateとSQLの記述位置を維持できる。
- 代替案: SQLをDB StateへIR上で統合すると入力上の独立したイベントという意味が失われる。
- 配置と依存: `src/core/layout/sequence-layout.ts`が連続する表示パネルの寸法と位置を決め、`render-preview.ts`が安全なSVGノードを描く。

### D-04 - フラグメントの前面ラベルと動的な間隔

- 対象: REQ-025 / REQ-025-S01、REQ-025-S02。
- 選択: フラグメントの種類を背景と境界付きのSVGラベル、caseとelseを枠と背景のない`#DD6872`のSVGテキストにし、既存の最後に描く前面順を保つ。
枠は透明のままとし、ラベルがイベントに重ならない高さをCoreで確保する。
`case`と`else`のラベルを分岐線より下へ置き、最初のcase文字は`alt`ラベルの下端から12px以上離す。
caseの文字基準線は従来の座標を維持し、枠を除いた文字の上端を枠上辺から30pxから36pxに収める。
elseの文字基準線も従来の座標を維持し、分岐線の下に8px以上の空きを確保する。
分岐の前後で重なる同一Objectの活性区間は1本に統合し、継ぎ目の水平線を残さない。
Object間の距離をメッセージと処理の幅で決め、State幅を全量そのまま隣のライフライン間隔に加える方式を見直す。
Stateはイベントの縦位置に出し、次のイベントとの縦方向の衝突を避ける。
他のライフラインの破線がStateの背後を通ることは許すが、文字、活性、矢印、カード、分岐ラベルの相互遮蔽は許さない。
- 理由: 現行画像の大きなDBとFILEの空白を減らしつつ、内容の長さによる再配置を維持する。
- 代替案: 試作の数値座標を移植すると長い文言や入れ子で破綻する。
- 配置と依存: Coreが寸法と座標を決め、Webviewはレイアウト結果を描く。

## Verification Plan

- 正常、境界、異常: [各シナリオ](specs/preview-appearance/spec.md)をPlaywrightで検証する。
解析の異常系はDSLの意味を変更しないため既存テストで回帰を確認する。
- 非機能要件: 新規のNREQはない。
既存の編集応答時間を`npm run check`と既存テストで回帰確認する。
- 手動確認: ChromiumでHTML試作と新しい基準DSL画像を並べ、配色、情報階層、パネルと分岐の見え方を確認し、比較画像と結果を台帳に記録する。
VS Code開発ホストのダーク・ライト両テーマでWebviewとエディタを確認する。
- 全体検証: `npm run check`、`npm run test:visual`、`npm run test:extension`、`npx --no-install openspec validate align-preview-with-html-sample --strict`を成功させる。

## Risks / Trade-offs

| 対象IDまたは設計節 | リスクや制約 | 対処と検証 |
| --- | --- | --- |
| D-02 | SVGテキストと背景の計測差でラベルが切れる | Chromiumで実際の境界を取得し、長文も確認する |
| D-03 | SQL結合で独立イベントが消える | StateとSQLの表示数と記述順を検査する |
| D-04 | 間隔の縮小でStateが他の要素を隠す | 交差判定と基準DSL、長文、入れ子の画像を確認する |

## Migration Plan

DSL、設定、保存データの移行は不要である。
外観変更に問題があればSVGとCSS、レイアウトの差分を戻し、既存の仕様と視覚テストの結果を維持する。
