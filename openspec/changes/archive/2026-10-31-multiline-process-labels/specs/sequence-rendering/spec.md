# Spec Delta

## MODIFIED Requirements

### Requirement: REQ-008 - 活性と処理の表現

WHEN 活性操作と処理を描画したとき、GlitchFlowは SHALL 活性を明示された`Object+`から`Object-`まで連続して表示し、処理を該当ライフラインの位置に入力どおりの行数で表示し、強調処理を太字にする。\
複数行処理の各行の幅と全体の高さを配置へ反映し、後続のイベントやフラグメント境界と重ねない。

#### Scenario: REQ-008-S01 - 活性と処理を表示する

- **GIVEN** `FE+`、`FE: *起動処理*`、`Global ->> FE: 入力`、`FE-`を順に含む文書がある。
- **WHEN** 図面を描画する。
- **THEN** FEの活性は入力メッセージの位置を通過し、FE-の位置で終了する。
- **AND** 起動処理はFEに結び付いて太字で表示される。

#### Scenario: REQ-008-S02 - 構文エラーを含む文書の描画

- **GIVEN** 未宣言オブジェクトへのメッセージと、宣言済みFEの処理を含む文書がある。
- **WHEN** 図面を描画する。
- **THEN** 未宣言オブジェクトの座標を作らず、FEと処理を表示できる。

#### Scenario: REQ-008-S03 - 複数行処理の時間軸を確保する

- **GIVEN** FEの活性中に3行の処理があり、その後にメッセージと`FE-`がある。
- **WHEN** 図面を描画する。
- **THEN** 3行の処理をFEの位置に入力順で表示し、メッセージと活性終了は処理の下に配置される。
- **AND** 処理の長い行が隣のObject枠や表示領域の右端で切れない。
